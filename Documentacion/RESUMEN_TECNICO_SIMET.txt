3. PROBLEMA DE LAS GRAFICAS VACIAS
----------------------------------

La base de datos contenia lecturas historicas hasta aproximadamente marzo de 2026, pero el backend utilizaba:

datetime.now()

Como la fecha de ejecucion era posterior, las consultas buscaban lecturas en un periodo sin datos.

Por ejemplo, el backend preguntaba por el dia o mes actual del servidor, aunque la ultima lectura disponible pertenecia a marzo de 2026.

La solucion fue obtener la fecha maxima disponible:

referencia = db.scalar(
    select(func.max(Lectura.ts))
    .join(Medidor, Lectura.id_medidor == Medidor.id_medidor)
    .join(Servicio, Medidor.id_servicio == Servicio.id_servicio)
    .where(*zona_filtros)
) or datetime.now()

A partir de esa fecha se calculan:

- Dia de la ultima lectura.
- Ultimos siete dias disponibles.
- Ultimos treinta dias disponibles.
- Mes de la ultima lectura.
- Ultimas veinticuatro horas con datos.

Esto permitio que las graficas consultaran periodos donde realmente existen lecturas.

6. ERROR SQL DE GROUP BY
------------------------

El endpoint devolvia HTTP 500 con el error de PostgreSQL:

column "lectura.ts" must appear in the GROUP BY clause or be used in an aggregate function

La causa fue utilizar tres expresiones SQLAlchemy distintas:

func.date_trunc("hour", Lectura.ts)

una en SELECT, otra en GROUP BY y otra en ORDER BY.

SQLAlchemy genero parametros separados para cada expresion. PostgreSQL no las trato como una expresion identica.

La solucion fue crear una sola expresion reutilizable:

periodo_hora_zona = func.date_trunc(
    "hour",
    Lectura.ts,
).label("periodo")

Luego se utilizo el mismo objeto en:

- select()
- group_by()
- order_by()

Esto corrigio el error 500 del endpoint.

10. DECISION DE USAR CARTOGRAFIA REAL
-------------------------------------

Se decidio no presentar poligonos inventados como limites oficiales.

Para dibujar zonas reales se requeria un archivo GeoJSON con:

- FeatureCollection.
- Features.
- Propiedades de cada delegacion.
- Geometria Polygon o MultiPolygon.
- Coordenadas reales en formato longitud y latitud.

Se identifico la capa:

POLIGONOS_DELEGACIONES_UNIFICADO.geojson

La capa incluye propiedades como:

- fid
- Delegacion
- NOMBRE_DEL

Y geometria MultiPolygon con coordenadas reales.


11. GENERACION DEL ARCHIVO GEOJSON
----------------------------------

Como el archivo no podia subirse directamente al chat, se probaron varias alternativas:

- Copiar el JSON desde el portapapeles.
- Generarlo mediante PowerShell.
- Generarlo mediante Python.
- Descargarlo directamente desde la fuente.

El metodo que funciono fue el script:

descargar_zonas_toluca.py

Este script:

1. Prueba varias URL de descarga.
2. Descarga el GeoJSON real.
3. Verifica que sea una FeatureCollection.
4. Comprueba que contenga Polygon o MultiPolygon.
5. Elimina la tercera coordenada Z igual a 0.0.
6. Conserva longitud y latitud.
7. Agrega una propiedad de fuente.
8. Crea automaticamente la carpeta public/data.
9. Guarda el resultado como UTF-8.
10. Vuelve a leer el archivo para validarlo.

El resultado fue:

public/data/zonas_toluca.geojson

con:

- Tipo: FeatureCollection.
- 47 features.
- 47 poligonos geograficos reales.
- Tamaño aproximado generado: 44,175 bytes.

El archivo puede comprobarse en desarrollo con:

http://localhost:5173/data/zonas_toluca.geojson

o con el puerto configurado por el proyecto:

http://localhost:8443/data/zonas_toluca.geojson

13. ERROR DE IMPORTACION DE LEAFLET
-----------------------------------

Aparecio el error TypeScript:

'LeafletGeoJSON' cannot be used as a value because it was imported using 'import type'

La causa fue importar GeoJSON de Leaflet solamente como tipo y luego intentar instanciarlo.

Importacion incorrecta para crear objetos:

import type { GeoJSON as LeafletGeoJSON } from "leaflet";

La solucion fue importar la funcion real:

import { geoJSON as createLeafletGeoJSON } from "leaflet";

Y utilizar:

const temporal = createLeafletGeoJSON(geojson);
const bounds = temporal.getBounds();

El tipo LeafletGeoJSON puede seguir importandose con import type para tipar referencias, pero no para crear una instancia en tiempo de ejecucion.


14. DIFERENCIA ENTRE 46 ZONAS Y 47 POLIGONOS
---------------------------------------------

La tabla energia.zona contiene 46 zonas energeticas.

El GeoJSON descargado contiene 47 poligonos territoriales.

Estas clasificaciones no coinciden uno a uno.

Ejemplos de coincidencia directa o aproximada:

- SAN PABLO AUTOPAN -> San Pablo Autopan
- SAN CRISTOBAL HUICHOCHITLAN -> San Cristobal Huichochitlan
- SAN BUENA AVENTURA -> San Buenaventura
- SAN MATEO OTZCACATIPAN -> San Mateo Otzacatipan

Ejemplo de correspondencia no directa:

- CENTRO HISTORICO -> Toluca de Lerdo

Tambien existen zonas energeticas que pueden ser fraccionamientos, conjuntos urbanos o subdivisiones sin poligono independiente en la cartografia.

Por ahora el mapa muestra los 47 poligonos territoriales reales.

Para conectar consumo, medidores y alertas con cada poligono se necesita una tabla o archivo de equivalencias entre:

- id_zona y nombre de energia.zona.
- fid y NOMBRE_DEL del GeoJSON.

17. FLUJO ACTUAL DEL DASHBOARD
------------------------------

1. React carga Dashboard.tsx.
2. dashboardService.ts consulta /api/dashboard.
3. FastAPI obtiene la ultima fecha de lectura disponible.
4. FastAPI calcula indicadores, series y consumos por zona.
5. React dibuja tarjetas y graficas.
6. Dashboard.tsx inserta MapModule.
7. MapModule solicita /data/zonas_toluca.geojson al servidor Vite.
8. Leaflet dibuja los 47 MultiPolygon reales.
9. El usuario puede buscar, seleccionar y resaltar delegaciones.
